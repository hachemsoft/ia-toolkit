Managed settings generated by AI Kit {version} from organization.toml.

Deploy each file with your device management (MDM, Group Policy) or the vendor's admin console, to the place
below. They take precedence over what a person, a repo or an agent writes. Check each key against the CLI version
you deploy: the vendors change them between releases.

claude-code/managed-settings.json
  macOS   /Library/Application Support/ClaudeCode/managed-settings.json
  Linux   /etc/claude-code/managed-settings.json
  Windows C:\Program Files\ClaudeCode\managed-settings.json
  Denies agent edits to the kit's and Claude Code's configuration, and runs the guardrails: {hooks}.{hooks_only}

gemini-cli/settings.json (system settings)
  macOS   /Library/Application Support/GeminiCli/settings.json
  Linux   /etc/gemini-cli/settings.json
  Windows C:\ProgramData\gemini-cli\settings.json
  Runs the guardrails ({hooks}) and turns YOLO mode off.

codex/requirements.toml
  macOS and Linux  /etc/codex/requirements.toml
  Windows          %ProgramData%\OpenAI\Codex\requirements.toml
  Keeps the sandbox on: the agent writes only inside the repo it works in.

The guardrails run each person's copy of the kit ($HOME/.ai-kit), so the kit stays installed per person, as usual.
The hook commands use $HOME: on Windows, Claude Code and Gemini CLI run them through their shell; try them on one
workstation first. Antigravity CLI has no documented central policy: its guardrails stay those the kit installs.
