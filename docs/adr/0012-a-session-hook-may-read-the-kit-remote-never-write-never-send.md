> Superseded: the `whats-new` hook reads only the local copies of `CHANGELOG.md` and `NEWS.md` in `~/.ai-kit/news/`, never the network; a newer Core is reported by `ai-kit status` from the last `sync` (ADR 0025).

# A session-start hook may read the kit's own remote once a day, never write, never send

The kit's only channel to a person was the terminal line of `update`: those who do not run it never hear of a version, and nothing could announce a skill or a training. A `SessionStart` hook, declared by every adapter next to the guardrails, now injects into the agent's context, once, what is new: the installed version's CHANGELOG section, the entries of the repository's `NEWS.md`, and "a newer version is available". For the last two it may run `git fetch` on the kit folder's `origin`, at most once a day, with a hard timeout (the process tree is killed, no prompt from git, ssh or a credential helper), reading `VERSION` and `NEWS.md` on origin's default branch (else the branch the clone tracks, else `main`) without touching the working tree: the fetch writes only `.git/FETCH_HEAD` and the remote-tracking ref. Every failure is silent, recorded as a category (`network`, `auth`, `no ref`, `timeout`), never as git's own text, and only reported by `doctor`. The hook never writes outside `~/.ai-kit/news.json`, never sends anything, and never runs `update`: the agent proposes, the person runs `ai-kit update` in a terminal; a refusal is recorded by `ai-kit news --later` and silences the proposal until the next version. Organization-specific announcements live in the organization's copy of the repository (ADR 0009), and reach workstations through the same remote `update` pulls.

ADR 0004 stays as it is: the installer, `doctor` and the tests still make no network call. This decision bounds the one exception: a read of the kit's own remote, from a hook, under the person's git identity, that the organization can turn off in `defaults` and the person in `overrides.toml`. `ai-kit news --check` is the same read, on request, and the agent may run it when the person asks. The other side of the trust: what is on the remote's `NEWS.md` reaches every session's context the next day without any action of the person, so pushing to that branch is pushing into the agents' context, with the same trust as pushing a skill that `update` installs.

**Considered**: announcing only in the terminal at `update` (reaches nobody who does not update); a URL declared in `organization.toml` (a second network access and a second thing to secure, for the same file the remote already holds); the hook running `update` on the person's yes (rewrites the CLIs' settings mid-session and makes Codex and Gemini re-ask trust; against ADR 0006); a `systemMessage` next to the context (rendered differently by each CLI, invisible in some). Rejected for the reasons given.
